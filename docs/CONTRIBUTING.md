# Contributing Guidelines

## Getting Started

1. Fork the repository
2. Create a feature branch from `develop`
3. Make your changes
4. Submit a pull request

## Branch Naming

```
feature/feature-name          # New features
fix/bug-description           # Bug fixes
docs/documentation-name       # Documentation
refactor/component-name       # Code refactoring
```

## Commit Messages

Use clear, descriptive commit messages:

```
feature: add repair booking calendar
fix: correct RTL layout on mobile devices
docs: update installation instructions
refactor: simplify repair status checker
```

## Code Style

- Use ESLint for JavaScript/TypeScript
- Format code with Prettier
- Follow existing code patterns
- Use meaningful variable names
- Add comments for complex logic

## Testing

- Write tests for new features
- Ensure all tests pass before submitting PR
- Test on both desktop and mobile
- Test both Arabic and English interfaces

## Pull Request Process

1. Update documentation if needed
2. Add/update tests
3. Ensure code passes linting
4. Provide clear description of changes
5. Link any related issues
6. Request review from maintainers

## Issue Reporting

Include:
- Clear title and description
- Steps to reproduce (for bugs)
- Expected vs actual behavior
- Screenshots/videos if applicable
- Environment details (browser, device, OS)
